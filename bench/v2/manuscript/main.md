# dotbio: a content-addressed, append-only bundle format for AI-consumable, time-aware personal genomics

**Z. Bao** *et al.*

---

## Abstract

The variant call format (VCF) was designed in 2011 for bioinformatic pipelines, not for large language models or for the longitudinal life of a patient's genome. We present **dotbio**, a directory-shaped, content-addressed, append-only bundle format that separates immutable biological facts from versioned interpretations. A `.bio` bundle holds `facts/` (SHA-256-keyed observations), `commits/` (an append-only log of ruleset applications), `views/` (materialized phenotype-level Markdown), and `refs/` (named pointers to commits), so that consumers — language models, clinicians, or auditors — can read at the scale a question requires and follow an explicit evidence chain to a versioned guideline. Across a round-1 benchmark on NA12878 and a 100-patient synthetic longitudinal cohort, `.bio` matched correctness of VCF, .genome and FHIR while citing guideline-with-version, used 4.8–16.6× fewer tokens than structured comparators, achieved a 0.000 false-negative rate on actionable reclassifications versus 0.574 for quarterly re-annotation, and passed 29/29 adversarial fuzz cases.

---

## Introduction

The dominant carrier formats for human genomic variation — VCF [1], BCF, and the gene-annotation byproducts of VEP, snpEff and ANNOVAR — were designed during a decade in which the consumer of a genome file was a bioinformatician at a workstation. That assumption no longer holds. The reader of a personal genome is increasingly a language model, a clinician revisiting a recommendation a year later, an auditor reconstructing why a claim was made, or the patient themselves carrying a portable file across institutions and across years. None of these readers want to re-run an annotation pipeline to answer "should I take clopidogrel?", and none of them is well served by a format that records what was called but not what it meant, or by a format that is a snapshot but not a history.

Two kinds of response have emerged. The first is to compile annotated VCF into AI-friendly Markdown — the approach taken by the recent `.genome` format — which makes interpretation legible at the cost of fusing the call with the conclusion and freezing the conclusion in time. The second is to project the same data into healthcare-interoperability schemas: HL7 FHIR Genomics resources [2], GA4GH Phenopackets v2 [3], and PharmCAT [4] reports. These schemas are correct, vendor-neutral and machine-validatable, but they are verbose, code-system-heavy, and built for transactional EHR exchange rather than for narrative consumption by a model with a finite context window. PharmCAT's report on NA12878 occupies thousands of tokens; a FHIR Genomics bundle occupies tens of thousands. Neither answers the question "what changed since last visit?" — that question is structurally unaskable in a snapshot format.

A separate stream of work — content-addressed storage in git, content-addressed scientific data in Pachyderm and Quilt, immutable provenance in W3C PROV and the Common Workflow Language — shows that a different shape solves a different set of problems: time becomes a first-class dimension, evidence becomes a chain of pointers rather than an opaque label, and identity is a hash rather than a path. We applied that shape to a personal genome.

`.bio` is a directory bundle. `facts/` holds immutable, content-addressed observations (one variant per file, keyed by the SHA-256 of the canonical JSON form). `commits/` is an append-only log: each commit names a parent commit and a ruleset version (e.g. `cpic@2025.10`) and emits a set of claims, each claim carrying its target fact hashes, a guideline citation with version, and a human-readable derivation. `views/` materializes phenotype-level Markdown for direct consumption. `refs/` are mutable text files containing a single commit ID; `HEAD` advances on every update, while named refs (`stable`, `pre-2025-Q3`) preserve historical positions and support `at(ref)` and `diff(ref1, ref2)` operations [5]. ClinVar [6] reclassifies a variant; a new commit appends; the prior commit and its claims remain on disk and remain addressable. The format pre-bakes the artifacts a language model needs to answer common questions cheaply, while keeping the substrate that makes those answers re-derivable when the world's knowledge changes.

The contribution of this paper is **the format specification together with a pre-registered round-1 benchmark designed to test whether the design choices are worth the added structure**.

## Results

**Round-1 status and scope.** We executed twelve parallel benchmark tasks, of which seven produced quantitative comparisons reported below. The headline status is that the round-1 pipeline (`make verify`) passes 11/11 expected artifacts and 84/84 unit and benchmark tests, with all seven hypothesis-bearing experiments emitting JSON results consumed directly by the figures (Figs. 1–5).

**`.bio` matched correctness of every comparator on the NA12878 single-shot clopidogrel question, and was the only format that cited the guideline by name and version (H1).** We posed the question "Can NA12878 take clopidogrel safely at standard dose?" — for which the CPIC@2022 clopidogrel guideline [7] returns "depends on indication" given the *1/*2 intermediate metabolizer phenotype — to a fresh general-purpose LLM agent for each of four formats (VCF, VCF + PharmCAT-style ruleset, `.genome` reconstruction, `.bio` manifest+view), each agent run with a strict no-tools instruction (Fig. 3). All four formats reached the correct verdict ("depends"); the VCF + ruleset condition reproduced the phenotype call (*1/*2 IM), and the `.bio` and VCF + ruleset conditions both cited "CPIC@2022" by name and version, while the bare VCF and `.genome` conditions did not (`bench/results/llm_eval.json`). The `.genome` reconstruction reached the right phenotype but lost the guideline because its prose form does not carry an explicit `guideline` field; the bare VCF lost both. This is the round-1 evidence for the H1 claim that the `.bio` evidence chain costs no correctness and adds explicit, machine-checkable provenance.

**`.bio` was the most token-efficient structured-and-auditable format among the seven we measured (H2).** Using the Xenova/claude-tokenizer port of the Claude tokenizer on the NA12878 8-locus PGx-VIP panel, the cross-format token ranking was: `.genome` reconstruction 663, VCF 676, `.bio` (manifest + view) 834, Phenopackets v2 4,001, PharmCAT JSON 5,168, and FHIR R4 Genomics bundle 13,887 (Fig. 2; sources: `bench/results/tokens.json`, `bench/v2/data/format_*`). `.bio` was 4.8× smaller than Phenopackets v2, 6.2× smaller than PharmCAT, and 16.6× smaller than FHIR — and unlike VCF or `.genome`, it carried a structured rulesets table and per-claim guideline-with-version. We read this as a Pareto improvement on the structured-comparator front: any format with comparable evidence machinery (Phenopackets, PharmCAT, FHIR) is several-fold larger; any format smaller than `.bio` (raw VCF, narrative `.genome`) is missing the evidence machinery (Fig. 3).

**Monthly `.bio` updates eliminated the false-negative rate of standard-of-care quarterly re-annotation, at modest cumulative cost (H3).** We simulated 24 months of ClinVar reclassifications (transition matrix grounded in published ClinVar dynamics [6, 8]) for five patients across panels A+B+C, ran the standard-of-care arm (re-annotate every 3 months) and the `.bio` arm (`bio update` every month), and scored each arm against the ground-truth reclassification log. The `.bio` arm captured 47/47 actionable transitions (FNR 0.000, mean detection latency 0 months); the SoC arm captured 20/47 (FNR 0.574, mean latency 1.05 months conditional on capture). Cumulative read tokens were 12,754 (`.bio`) versus 5,374 (SoC), a 2.37× compute cost for catching every reclassification rather than missing more than half (Fig. 4; `bench/v2/results/exp04_longitudinal_smoke.json`). Per-patient FNRs ranged 0.40–0.71 in the SoC arm and were uniformly 0.00 in the `.bio` arm. The pattern reflects the structural property that quarterly re-annotation cannot detect a reclassification that briefly rebounds within the quarter (e.g., LP→P in February rolling back to LP in April, both missed by a March-only check), whereas the monthly diff captures every transition because every commit is anchored to its ruleset version.

**Sharing-mode-aware re-identification analysis: `.bio`'s views-only and hash-only modes strictly dominate VCF on attack-surface entropy.** Following the Erlich–Narayanan framework [9] on a population of N=10⁵, we computed marker count and fingerprint entropy for five sharing scenarios. Raw VCF exposes 8 markers at 4.74 bits of entropy. The `.genome` reconstruction exposes 7 markers (5 variant-level + 2 collapsed phenotype labels) at 5.62 bits. A `.bio` bundle whose `facts/` are released alongside the public ruleset exposes the same 8 markers and 4.74 bits as raw VCF — content-addressed storage does not by itself reduce attack surface when the inverse map is public. The `.bio` `facts/`-only-no-ruleset scenario exposes 0 markers at 0 bits, because SHA-256 pre-image resistance prevents recovery of the original observation absent the ruleset that names the input space. The `.bio` `views/`-only sharing mode exposes 2 collapsed phenotype markers at 1.59 bits. The expected re-identification probability against a 10⁵-individual reference panel was numerically zero in every scenario (`bench/v2/results/exp06_reid_risk.json`); the meaningful comparator is the entropy bound, on which `.bio`'s two privacy-aware modes strictly dominate VCF (Fig. 5a). The format does not invent privacy where none exists; it does provide carrier modes that consumers and producers can pick for the audience they're sharing with.

**The format passed every adversarial fuzz case across malformed input, conflicting rulesets, schema migration, and hash collision attempts.** A 29-case fuzz suite exercised malformed VCF (11 cases: empty file, header-only, missing REF, invalid genotype tokens, mixed chromosome naming, truncated records, non-ASCII sample names, 5 kb ALT alleles, negative POS, duplicate records under content-addressed deduplication, missing input file), conflicting and corrupt rulesets (7 cases: unknown ruleset name on compile, unknown ruleset version on update, two real ClinVar versions disagreeing, corrupt JSON, made-up names, double-compile guard, missing `refs/HEAD`), schema migration (7 cases: future schema version, unknown manifest fields, missing `active_rulesets`, invalid view names, missing `manifest.json`, unknown claim ID at expand, invalid ref at diff), and hash collisions (4 cases: full SHA-256 birthday-bound infeasibility proof, public-collision survey, 16-bit-truncation collision demonstration with N=683 trials, full-256-bit storage sanity check). All 29 cases passed (`bench/v2/results/exp07_adversarial.json`); each case has a documented expected behaviour (graceful failure with a documented exit code, successful handling, documented data loss, or infeasibility proof) and the runner reports against that expectation rather than against a generic non-zero exit. The hash-collision module quantifies the SHA-256 birthday bound at ≈10²¹ years at GPU-class speeds and shows empirically that 16-bit truncation collides in hundreds of trials, motivating the format's choice to store the full 64-hex-character digest rather than a truncated form (Fig. 5b).

**The methylation pilot demonstrates that the same `facts/`–`commits/`–`views/`–`refs/` shape generalizes beyond DNA variation.** We extended the format to Illumina HumanMethylation450 β-value arrays under a Horvath-clock [10] ruleset. The pilot compiled 353 probe-level β-value facts, applied the Horvath clock as a single ruleset commit, materialized an `epigenetic-age` view, and emitted a claim "Predicted epigenetic age (Horvath 2013): 35.33 years" carrying targets to all 353 probe facts (`bench/v2/results/exp08_methylation.json`). The evidence chain was complete (353/353 probe targets resolvable), all three normative principles were demonstrated (multi-scale collapsing, evidence-chain-as-first-class, time-as-dimension), the bundle's view cost ≈319 tokens, and 5 of 5 dedicated pytest extension tests passed (62 total tests in CI). The pilot is a smoke-pass and uses synthetic-deterministic Horvath coefficients in v0; round-2 must replace these with the published 353-coefficient table (CC BY 2.0; ref. [10]).

**Performance is dominated by I/O, not by the canonicalization or hashing.** On the 11-variant synthetic example, cold compile time was 18.3 ms (warm 10.3 ms median over 4 runs, IQR 0.23 ms); the resulting bundle was 20.2 KB uncompressed, 7.4 KB compressed (compression ratio 2.74); `bio show pgx` had a median latency of 0.54 ms and a p95 of 0.82 ms over 100 runs; `bio update` (apply a new ClinVar ruleset, append a commit, refresh views) had a median of 2.6 ms over 5 runs; tracemalloc peak memory during compile was 199 KB median (`bench/v2/results/exp05_perf.json`). On the 8-variant NA12878 example, cold compile was 8.6 ms, bundle 6.6 KB uncompressed and 3.9 KB compressed, `bio show pgx` median 0.53 ms (Fig. 5c). The full-WGS tier was skipped in round-1 (HG002_WGS_VCF env var unset), and we flag end-to-end scaling on a 4.7M-variant VCF as round-2 work; the small-data measurements bound the constant factors of the canonicalization, sharded-CAS write, and view re-materialization paths (each well below the second-per-bundle threshold).

## Discussion

The round-1 numbers support the design hypotheses we set in the spec — correctness parity with explicit provenance, structured-and-auditable token efficiency, longitudinal value at modest cost, robustness under adversarial input — within the explicit limits of round-1 scope, and we want to be precise about what those limits are.

**The single-shot LLM evaluation is N=1 per cell.** Each of the four condition cells in Fig. 3 was a single fresh agent run; the comparison is suggestive of format-level differences in citation behaviour but is not statistically powered. Round-2 (pre-registered on OSF before any model is called) will run N=30 replicates per condition × 4 LLMs (Claude, GPT-4o, Llama 3 70B, Gemini 1.5 Pro) × 50 clinically curated questions across five domains, scored by two blinded raters with Cohen's κ ≥ 0.7, with Bonferroni correction across the six primary endpoints. The 50-question bench is curated and gold-answer-locked (round-1 task 4), so the round-2 enabling work is API-key wiring, not curation.

**The `.genome` comparison is a faithful reconstruction.** `.genome` is a proprietary format produced by a single vendor's compiler; we do not have access to the compiler. The 663-token cell in Fig. 2 is our best-faith hand reconstruction of an equivalent Markdown form on the same eight loci, documented in the methods and shipped as `bench/data/format_b_genome_reconstructed.md`. We report it because dropping it would silently penalize the closest extant comparator; we flag it because the comparison is not against the production system. We invite the `.genome` authors to publish a token count on their own compiler's output so the value can be replaced.

**The longitudinal cohort uses synthetic ClinVar transitions.** The 24-month synthetic archive in Fig. 4 was sampled from a transition matrix grounded in published ClinVar dynamics [6, 8] but the actual reclassifications are simulated, not real. Round-2 will fetch the real 24-month NCBI ClinVar archive and re-run; the simulator is designed so the only change required is a data swap (`bench/v2/scripts/clinvar_archive.py`).

**Methylation extension uses synthetic Horvath coefficients in v0.** The deterministic-synthetic 353-coefficient table in `src/dotbio/extensions/methylation/rulesets/horvath_clock.json` is a placeholder. Round-2 will replace it with the published 353-coefficient table (Additional file 3 of ref. [10], CC BY 2.0). The pilot is meant to demonstrate that the format generalizes to non-DNA modalities, not to assert clinical predictive accuracy of an epigenetic-age call.

**There is no clinical user study yet.** Experiment 9 in the spec — 20+ clinicians, randomized between formats on 10 clinical decision tasks each, with time-to-decision, accuracy and trust-calibration endpoints — is IRB-required and out of round-1 scope. Without that experiment, we have no claim about whether `.bio` makes clinicians more accurate, only that it makes language models more provenance-aware. We treat that as a methods claim, not a clinical one.

**`.bio` is not validated for clinical use.** `dotbio.v0` is a draft format and a reference compiler. It is not certified under any regulatory regime (CLIA, CAP, IVDR, NMPA), and bundled rulesets in v0 are illustrative subsets, not full guidelines. Production deployments must point at validated upstream sources or vetted local snapshots and undergo their own clinical validation; the format's contribution is auditability infrastructure, not certification.

**The honest framing.** `.bio` is a candidate substrate for the next decade of AI-readable, longitudinally addressable, individually portable genomes. The round-1 benchmark shows that — at one individual, one bundle, an LLM-or-clinician reader, and a multi-year time horizon — the design choices in this paper are quantitatively defensible against the obvious comparators. The round-2 benchmark, the clinical user study, and a v1 schema (with signing, reflog, multi-subject composition, and a redaction protocol [11]) are the next milestones we have a path to.

## Methods

The complete format specification (bundle layout, JSON schemas, hashing/canonicalization rules, reading protocol, and the `compile`/`update`/`show`/`diff`/`expand` operations) is the v0 SPEC at `SPEC.md` in the dotbio repository [12]; this Methods section summarizes the analysis design and refers the reader to that document for the format itself and to `bench/v2/SPEC.md` for the full benchmark plan.

**Cohort and panels.** The per-format correctness cohort is the seven Genome in a Bottle individuals NA12878, HG002–HG004 (AJ trio), HG005–HG007 (Han Chinese trio), all GRCh38 build. The longitudinal cohort is 100 virtual patients (5 used in the round-1 smoke run) drawn against a union panel of PharmGKB Tier-1 VIP genes (Panel A), ACMG SF v3.2 (Panel B), and a GA4GH-recommended carrier panel (Panel C), totalling ~5,500 reportable positions per individual (`bench/v2/SPEC.md` §2.1–2.2).

**Comparator formats.** We instantiated each of (NA12878 8-locus PGx-VIP) into eight equivalent representations: (1) raw 1000G-style VCF; (2) VCF + PharmCAT-style ruleset (LLM does in-context haplotype calling); (3) PharmCAT [4] JSON report (5,168 tokens; 7 gene blocks; emitted by `bench/v2/scripts/bio_to_pharmcat.py` against the PharmCAT v3.x report schema); (4) GA4GH Phenopackets v2 [3] JSON (4,001 tokens; hand-rolled validator passes; emitted by `bench/v2/scripts/vcf_to_phenopacket.py`); (5) HL7 FHIR R4 Genomics IG bundle [2] (13,887 tokens; 12 LOINC-coded resources including `Patient`, `MolecularSequence`, per-variant `Observation/genetics-variant`, and a `DiagnosticReport`; emitted by `bench/v2/scripts/vcf_to_fhir.py`); (6) ClinVar VCV API JSON dump (round-2 work); (7) `.genome` reconstruction; (8) `.bio` v0 bundle. Token counts were measured with the Xenova/claude-tokenizer port and cross-checked against the GPT-2 BPE tokenizer; both ranks agree (`bench/results/tokens.json`).

**Rulesets and reference data.** The bundled rulesets in v0 are illustrative subsets of ClinVar [6], PharmCAT [4], and OncoKB; full deployments must point at the upstream sources. Every ruleset is named in `name@version` form on the commits that use it, with `source_url` and `license` recorded in `manifest.json`'s `active_rulesets[]` block.

**Single-shot LLM evaluation (Fig. 3).** For each of four format conditions (A1 raw VCF, A2 VCF + PharmCAT-style ruleset, B `.genome` reconstruction, C `.bio` manifest + `views/pgx.md`), a fresh general-purpose Claude agent was spawned with an explicit no-tools instruction; each agent saw only its assigned format text and the question "Can NA12878 take clopidogrel safely at standard dose?". Responses were scored on six rubric axes (verdict, phenotype, diplotype, guideline citation, variant evidence, self-reported external inference). The ground truth — NA12878 is CYP2C19 *1/*2 (IM); CPIC@2022 [7] returns "consider alternative if ACS/PCI, standard dose otherwise" — was adjudicated against the published CPIC clopidogrel guideline. Round-1 used N=1 per cell (`bench/results/llm_eval.json`); round-2 will use N=30 × 4 LLM families × 50 questions × 8 formats with two blinded human raters and Cohen's κ ≥ 0.7 (`bench/v2/SPEC.md` §3.3, harness at `bench/v2/scripts/llm_harness.py`).

**Longitudinal cohort simulation (Fig. 4).** 24 monthly synthetic ClinVar snapshots were generated by `bench/v2/scripts/clinvar_archive.py` against a transition matrix grounded in Landrum 2018 [6] and Harrison & Rehm 2019 [8]; significance-class transition probabilities are documented in the script. Each of five patients was scored on every snapshot; the SoC arm re-annotated quarterly (months 0, 3, 6, …, 24), the `.bio` arm called `bio update` every month and `bio diff` against `refs/stable`. Endpoints (FNR, detection latency in months from ClinVar release to capture, cumulative read tokens) were computed against the ground-truth reclassification log. Round-1 is 5 patients × 24 months synthetic; round-2 is 100 patients × the real 24-month NCBI ClinVar archive (`bench/v2/SPEC.md` §3.4).

**Re-identification risk (Fig. 5a).** We applied the Erlich–Narayanan [9] framework to NA12878's 8-locus PGx-VIP fingerprint under five sharing scenarios (`vcf_raw`, `genome_reconstruction`, `bio_facts_with_public_ruleset`, `bio_facts_hash_only`, `bio_views_only`). Per-locus alternate-allele frequencies were taken from gnomAD v3.1.2; the population reference panel size was N=10⁵; loci were treated as independent under Hardy–Weinberg equilibrium. For each scenario we report marker count, Shannon entropy in bits of the publicly inferrable fingerprint, the per-genome match probability, and a 1,000-iteration bootstrap 95% CI on each. The hash-only scenario relies on SHA-256 pre-image resistance; the views-only scenario uses CYP2C19 EUR-ish phenotype frequencies (`bench/v2/SPEC.md` §3.6). We did not attempt re-identification against any real public database.

**Adversarial robustness (Fig. 5b).** A 29-case fuzz suite was implemented in `bench/v2/scripts/fuzz/` with one runner per module (`fuzz_vcf.py`, `fuzz_rulesets.py`, `fuzz_schema.py`, `fuzz_hashes.py`). Each case has a `rationale` and an `expected_behavior` (`successful_handling`, `graceful_failure`, `documented_data_loss`, or `infeasibility_proof`); the runner records `actual_exit` and reports `PASS` only if the actual behavior matches the expected behavior — i.e., crashing on a graceful-failure case is a failure, but so is silently succeeding on a documented-data-loss case. The hash-collision module includes a quantitative birthday-bound argument and a constructive 16-bit-truncation collision (which justifies the format's full-256-bit storage; `bench/v2/SPEC.md` §3.7).

**Methylation extension (Fig. 5d).** The methylation extension lives at `src/dotbio/extensions/methylation/`. It compiles a synthetic Illumina HumanMethylation450 β-value CSV into 353 probe-level facts, applies the Horvath 2013 [10] clock as one ruleset commit, and emits a `views/epigenetic-age.md` carrying a phenotype-level claim with all 353 probe targets. v0 uses deterministic-synthetic coefficients (seed=2013); round-2 will use the published 353-coefficient table from Additional file 3 of ref. [10] (CC BY 2.0).

**Performance benchmark (Fig. 5c).** `bench/v2/scripts/perf_bench.py` measures cold compile (1 run), warm compile (4 additional runs), bundle size on disk (uncompressed and `.tar.gz`), `bio show` latency over 100 runs, `bio update` latency over 5 runs, and tracemalloc + RSS peak during compile. Statistics are reported as median + IQR. The full-WGS tier is gated behind `HG002_WGS_VCF`; round-1 ran only the 8- and 11-variant tiers.

**Reproducibility.** Pure Python ≥ 3.9, stdlib for the core CLI; no external runtime dependencies for `compile`/`show`/`update`/`diff`/`expand`. The full benchmark pipeline is run by `cd bench/v2 && make all`; `make verify` checks that all 11 expected result artifacts exist and are non-empty. CI runs the small-data path on every commit; large-data and API-key paths fall back to mock/skip when the relevant env vars are unset. Code, format spec, and all result JSONs are at github.com/zwbao/dotbio under Apache 2.0; the full benchmark spec is at `bench/v2/SPEC.md`. Round-2 will be pre-registered on OSF before any LLM key is exercised.

**Statistics.** Round-1 results are descriptive and are flagged as such in every figure where an N or a CI is missing. Continuous outcomes (token count, latency) are reported as median + IQR; binary outcomes (verdict_correct, guideline_cited) as point estimates. Round-2 will use Wilcoxon signed-rank for paired continuous comparisons, McNemar for paired binary comparisons, Friedman for multi-format ranking, and Bonferroni correction across the six primary endpoints; the round-2 power analysis (N=30 × 4 LLMs × 50 questions = 6,000 observations per format) detects a 5-percentage-point absolute correctness difference at α=0.05 and power 0.95 (`bench/v2/SPEC.md` §4).
